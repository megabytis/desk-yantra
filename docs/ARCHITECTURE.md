OpenHands owns model inference, agent iteration, tool schemas and SDK events. This project owns provider connections/discovery, encrypted credentials, profiles, grants, exact-action approvals, companion execution, durable journal, artifact downloads and original UI. A custom tool routes all execution through the companion; unrestricted upstream terminal tools would bypass our execution-time permissions. SDK LocalWorkspace is used only for an app-owned scratch directory and no native terminal/file tools are registered.

The upstream TypeScript client targets the generic Agent Server API and would introduce browser-side runtime credentials or another proxy mapping. This product instead uses a small same-origin application API and SSE with HttpOnly pairing cookie, while Python directly owns SDK conversations. No production Node service is needed.

Selectively consulted `openclaw/openclaw:docs/gateway/security/index.md` for loopback/pairing boundaries and `open-webui/open-webui:backend/open_webui/routers/ollama.py` for local model discovery. These were read from upstream main on 2026-11-19 for design context only; no source copied or vendored. Further pinned reviews are recorded in UPSTREAM-REVIEW.md. The custom browser action uses persistent Playwright Chromium because the execution gate must remain authoritative.

Credential redaction happens before journal writes and tool observations. API connection representations omit encrypted keys. Companion commands get a minimal inherited environment. Runs persist normalized events rather than SDK credential-bearing conversation configuration. Restart conservatively marks all in-flight work for review.

Approval consumption uses a SQLite immediate transaction. Task budgets are shared persistently across delegation. Companion process groups are journaled with Linux process start times for crash cleanup. Terminal redaction buffers potential credential fragments across chunks. Host file tools reject traversal, links, special files and private state. Revocation synchronizes companion admissions with file operations/process launch; running processes are terminated.

Completed follow-up tasks preserve a conversation identifier and bounded prior results, while each new task gets fresh runtime state, authority checks and approvals. Companion HTTP access lives in a lightweight module so pairing and local stop do not initialize the SDK.

The model-facing toolset now uses focused SDK tools: list_directory, read_file, write_file, run_command, browse, delegate_task, capture_screen, and desktop_input. Only authorized operations are registered. The companion remains the execution-time authority. Nonzero tool exit statuses become error observations. File-only profiles can inspect projects and create nested files without shell permission.

Completed sandbox runs support user browser takeover through the same authenticated application API. Every direct user action is journaled with an exact approval; the companion rechecks grants. Takeover is permitted only after agent completion and marks the run paused. Host mode and concurrent agent actions are rejected. Conversation sandbox containers persist across follow-up runs. This is browser viewport control, not a host desktop integration or full VNC desktop.

Archival preserves connections and profiles because historical runs reference their IDs, and active workers may still need server-side credentials. New top-level and delegated tasks reject archived profiles/connections. Review resolution records a separate reviewed state, requires companion cleanup, cancels stale approvals, and permits a fresh follow-up; it never marks an uncertain action successful or resumes the interrupted command.

Limitations requiring continued work: full redaction of image/binary artifact content, resumable SDK conversation checkpoints, broader provider capability discovery, and live host pointer verification. Hyprland keyboard input is live-verified with wtype. Vision-capable model observations receive explicitly approved screenshots; text-only/unknown models receive references, and actual vision inference remains unverified. The product is single-user and local; it is not ready for untrusted multi-user hosting. Native desktop input commands follow the public [ydotool command interface](https://github.com/ReimuNotMoe/ydotool); no ydotool source is copied or bundled. The optional executable remains a separate user-installed dependency.

## State schema versioning — 2026-11-20

OpenAI Codex (GPT-6-sol) introduced SQLite `PRAGMA user_version` for Desk Yantra state. Version 0 is the pre-versioning layout; startup checks the baseline table layouts, creates missing tables/indexes and records version 1 in one SQLite transaction. An incompatible legacy layout fails without being stamped current. A database from a newer build fails startup rather than being silently downgraded. The backup tool rejects backups whose schema is newer than this build. Future schema changes need ordered migrations and old-state fixtures. Local Goose session migration code was consulted for versioning patterns; no source copied.
